# Hugging Face repository licensing

## Exact revision, tokenizer file, and applicable license

### Takeaway
At revision `914f7f89142e33e77833254d9c9b90c3cef7303b`, Hugging Face identifies `google/embeddinggemma-2` as `apache-2.0`; the exact-revision README and Google’s EmbeddingGemma 2 documentation also say Apache 2.0. `tokenizer.json` is a 32,170,510-byte file in that revision, but neither the Hub file listing nor the repository’s files attach a separate file-level license; the strongest official evidence is the model/repository-wide Apache 2.0 designation, not a distinct tokenizer license statement.

### Cited Findings
- The exact-revision Hugging Face model API reports `sha` equal to `914f7f89142e33e77833254d9c9b90c3cef7303b`, `cardData.license` as `apache-2.0`, and a `license:apache-2.0` tag. It lists `tokenizer.json` among repository files, and its siblings contain no file named `LICENSE`. [Hugging Face model API at requested revision](https://huggingface.co/api/models/google/embeddinggemma-2?revision=914f7f89142e33e77833254d9c9b90c3cef7303b)

The same response lists `tokenizer.model` separately at 4,689,013 bytes. [Hugging Face exact-revision tree API](https://huggingface.co/api/models/google/embeddinggemma-2/tree/914f7f89142e33e77833254d9c9b90c3cef7303b?recursive=true&expand=true)

[Google EmbeddingGemma 2 documentation](https://ai.google.dev/gemma/docs/embeddinggemma)

[Google Gemma Apache 2.0 license page](https://ai.google.dev/gemma/apache_2)
- Hugging Face’s documentation says a model card is the repository’s `README.md`, that card metadata can display the model’s license, and that `license` is a metadata field. This explains the Hub indicator’s source: it reflects repository card metadata; it is not a separately identified license declaration in the tokenizer file. [Hugging Face model-card documentation](https://huggingface.co/docs/hub/model-cards#model-card-metadata)

[Hugging Face exact-revision `.gitattributes`](https://huggingface.co/google/embeddinggemma-2/resolve/914f7f89142e33e77833254d9c9b90c3cef7303b/.gitattributes)
- Google’s general Gemma Terms of Use define “Gemma” as “the set of machine learning language models, trained model weights and parameters identified in the Appendix,” and its Appendix includes the name “EmbeddingGemma.” The page says its terms apply to models listed in that Appendix and directs users to separate Gemma 4 terms. The Appendix names “EmbeddingGemma” without a version number and does not name “EmbeddingGemma 2.” [Google Gemma Terms of Use](https://ai.google.dev/gemma/terms)

### Inferences
- **Interpretation, not a direct file-level declaration:** The exact-revision repository metadata and model card, corroborated by Google’s model-specific documentation, indicate Apache 2.0 for EmbeddingGemma 2 and therefore provide substantially stronger direct evidence for Apache 2.0 treatment of files distributed as part of this model repository than for the legacy Gemma Terms of Use.
- The official materials do not explicitly state “`tokenizer.json` is Apache-2.0” as a standalone file. The repository includes no `LICENSE` file and the file API does not expose per-file license metadata. Thus the record supports an Apache-licensed model/repository, but does not prove an independent file-specific grant beyond that scope.
- There is a wording ambiguity to preserve: the general Terms of Use Appendix includes the unversioned name “EmbeddingGemma,” while Google’s EmbeddingGemma 2 documentation separately and expressly says this v2 model is Apache-2.0. The official sources reviewed do not explain whether the Appendix’s unversioned entry was intended to include later version 2. For the requested v2 repository revision, the model-specific Apache statement is the more precise official statement; a definitive legal resolution of the Appendix’s scope is not supplied by these pages.

### Gaps
- No per-file license declaration or standalone tokenizer license file was present in the exact-revision Hub file listing. No official source reviewed expressly states the tokenizer’s license independently of the model/repository’s stated license.
- Google’s general Terms of Use Appendix does not explain the version scope of its unqualified “EmbeddingGemma” listing; the Google documentation reviewed does not expressly reconcile that entry with its model-specific Apache 2.0 statement for EmbeddingGemma 2.
